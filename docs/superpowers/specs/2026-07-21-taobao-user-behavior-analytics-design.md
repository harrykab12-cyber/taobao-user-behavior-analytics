# 淘宝用户行为数据分析作品集 - 设计说明

## 目标

构建一个可复现的国内电商数据分析与数据运营作品集，与简历中的“淘宝用户行为数据处理与业务分析”项目一致。项目通过真实、匿名化的淘宝用户行为数据，展示从数据清洗、SQL 建模、指标定义到 BI 看板和业务建议的完整分析流程。

## 求职定位与成功标准

目标岗位为数据分析实习生和数据运营实习生。项目完成后应让招聘方能在 GitHub 上快速验证以下能力：

- 使用 Python/pandas 完成可测试的数据清洗与质量校验。
- 使用 PostgreSQL 和 dbt 建立可追溯的分析数据模型。
- 明确定义并计算 PV、UV、漏斗转化率、留存率和复购率。
- 使用 Superset 展示运营看板，并将截图和导入说明保存在仓库。
- 用中文 README 和分析报告说明数据来源、方法、发现和可执行建议。

## 数据范围与使用边界

- 数据源：阿里云天池“淘宝用户购物行为数据集”。
- 数据性质：真实业务产生、经过匿名化处理的用户行为数据。
- 本项目只分析用户、商品、类目、行为类型和时间字段；不声称该数据代表当前淘宝业务或平台全量情况。
- 原始数据、可识别的明细数据和任何可重新分发的数据文件均不提交到 GitHub。
- 仓库只提交数据下载说明、字段说明、可复现脚本、汇总指标、图表和不含原始记录的示例数据。
- README 明确注明数据来源、仅作学习研究用途及相应的平台使用限制。

## 分析问题

项目围绕国内电商运营中常见的问题展开：

1. 用户从浏览到购买的各环节转化表现如何？
2. 用户在不同日期、小时和商品类目中的活跃与购买行为有何差异？
3. 新用户在后续周期的留存表现如何？
4. 哪些用户属于浏览型、意向型、加购未购型和复购型，可作为精细化运营对象？
5. 基于数据证据，可提出哪些转化、召回和类目运营建议？

## 技术架构与数据流

```text
天池原始 CSV（本地，不入库）
  -> Python/pandas 清洗与质量校验
  -> PostgreSQL 原始层与清洗层
  -> dbt 维度层、事实层、指标层
  -> Superset 数据集与运营看板
  -> Markdown 分析报告、图表与 README
```

### Python/pandas

Python 负责读取本地原始 CSV、校验字段与行为枚举、去除无效记录、解析 Unix 时间戳，并导出可载入 PostgreSQL 的标准化行为明细。清洗过程必须保留质量统计，避免把清洗规则藏在 Notebook 中。

### PostgreSQL + dbt

PostgreSQL 保存本地分析数据。dbt 将构建以下层次：

- `stg_user_behavior`：字段类型标准化、时间解析、行为名称映射。
- `int_user_daily_behavior`：用户日行为聚合。
- `int_user_funnel`：用户漏斗阶段和转化标记。
- `fct_daily_metrics`：日粒度 PV、UV、各行为人数、购买人数与漏斗转化率。
- `fct_retention`：按首日分群的留存指标。
- `fct_user_segment`：浏览型、意向型、加购未购型、购买型和复购型用户分层。
- `dim_item_category`：商品类目维度。

每个关键模型都配置 dbt 测试，覆盖非空、唯一性、行为类型合法性、时间顺序和指标分母有效性。

### Superset

看板分为三页：

1. 经营与漏斗概览：PV、UV、购买用户数、购买转化率、行为漏斗和日趋势。
2. 用户增长与留存：新增用户、活跃用户、留存热力图、时段分布。
3. 用户分层与品类运营：用户分层规模、加购未购用户、购买类目表现和运营机会。

仓库保存看板配置导出文件、所需数据集说明和截图，保证没有 Superset 服务时仍能查看成果。

## 错误处理与可复现性

- 缺少原始 CSV 时，脚本输出明确的下载路径和下一步说明，不自动下载或提交受限数据。
- 无效行为类型、无法解析的时间和关键字段缺失必须计入数据质量报告。
- 运行命令、环境变量模板和完整执行顺序写入 README。
- 合成样例数据支持不访问原始数据时运行测试和演示核心流程。

## 验证策略

- Python：使用 pytest，先写数据清洗与指标辅助函数的失败测试，再实现最小代码。
- dbt：运行模型测试并保存验证命令。
- 数据：在样例数据上验证漏斗计算、留存口径和用户分层结果。
- 交付前：从空环境按 README 执行，并检查 Superset 截图、报告链接和 Git 状态。

## Git 提交节点

每一个可独立验证的阶段单独提交：

1. 设计说明。
2. 项目骨架、环境配置和数据使用说明。
3. 样例数据与 Python 清洗测试、实现。
4. PostgreSQL 加载与 dbt 基础模型、测试。
5. 漏斗、留存和用户分层模型、测试。
6. Superset 看板配置与截图。
7. 分析报告、README 和最终验证。

## 非目标

- 不采集淘宝网页数据，不接触账号数据，也不处理任何个人可识别信息。
- 不建立实时数仓、推荐系统或机器学习模型。
- 不把原始天池数据上传到 GitHub。
